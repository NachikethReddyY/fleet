# Component Composition and States

Compose around the user's job. Familiar components provide behavioral contracts; change their presentation only when the task improves and the contract remains intact.

## Meaning before decoration

Give character to meaningful elements already present: links, selected controls, list markers, quotations, or section identifiers. One consistent treatment beats unrelated motifs.

Every accent, surface, gradient, pattern, shape, or illustration needs a named job such as identity, grouping, state, or brand. Keep it subordinate to content, responsive under real crops, sourced from accepted tokens, non-interactive, and outside the accessibility tree when decorative.

Custom controls retain native semantics, accessible names, keyboard behavior, focus, selection, and every interaction state.

Buttons need one clear purpose, concise action label or familiar symbol, adequate separation and target size, and immediate press feedback. Prefer conventional components when their semantics fit; familiar behavior is more valuable than novelty.

## Empty states

Design for the cause:

- **First use:** explain value and offer setup or creation.
- **No results:** name the query or filters and preserve ways to broaden them.
- **Removed or completed:** confirm the state and offer the next useful destination.
- **Unavailable or unauthorized:** explain the constraint and valid recovery.
- **Failure:** distinguish error from emptiness and offer retry or recovery.

Show only actions that work in the current state. Preserve navigation and filters needed for understanding or recovery. An illustration can set tone; explanation and next action carry the state. Test emptiness before relying on polished sample data.

## Structure

Use the quietest sufficient separator:

1. Proximity for groups on one plane.
2. Surface change for different roles or ownership.
3. Border for a persistent boundary or control edge.
4. Shadow for genuine elevation.

Combine cues only when one fails under real content or supported themes.

Treat component names as starting points, not fixed arrangements. Recompose when it improves scanning, comparison, comprehension, or action, while preserving semantics, focus order, selection model, dismissal, and responsive legibility. Reuse the constraint solved by a reference design, not its surface style.

## Gate

- Expressive treatments strengthen existing meaning and use governed tokens.
- Controls preserve their complete semantic and interaction contract.
- Every empty-state cause has an accurate explanation and usable next step.
- Decoration remains subordinate under real content and responsive crops.
- Separators use the fewest cues that make structure clear.
- Recomposed components improve a named task without surprising behavior.
- `DESIGN.md` and `DESIGN.html` record and demonstrate the same rules and states.
